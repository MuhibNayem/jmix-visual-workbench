# Contributing

Thank you for helping build Jmix Visual Workbench. Contributions must preserve
the source-authoritative, non-certified-by-default, clean-room product boundary.

## Before submitting

1. Read [CLEAN_ROOM.md](CLEAN_ROOM.md), [TRADEMARKS.md](TRADEMARKS.md), and
   [SECURITY.md](SECURITY.md).
2. Keep changes narrowly scoped and do not enable project mutation without the
   reviewed change-plan, compatibility, validation, and rollback controls.
3. Add tests or executable evidence appropriate to the change.
4. For compatibility behavior, cite the public specification, documentation,
   public issue, or openly licensed source and record its URL and license where
   relevant. Explain what was implemented independently.
5. Update third-party notices when a dependency is added or its license changes.

## Contributor attestation

By submitting a contribution, you attest that:

- you have the right to contribute it under the Apache License 2.0;
- it is your original work or uses material under a compatible, documented
  license;
- it does not use proprietary Jmix Studio code, assets, templates, protocols,
  decompilation-derived behavior, leaked information, or license bypass;
- any compatibility behavior includes sufficient public-source provenance for
  another contributor to reproduce the reasoning independently.

If you cannot make this attestation, do not submit the material. Contact the
repository maintainers to discuss a clean alternative.
